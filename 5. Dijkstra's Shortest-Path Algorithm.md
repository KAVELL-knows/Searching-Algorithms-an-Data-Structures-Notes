# Dijkstra's Shortest-Path Algorithm

**Dijkstra's algorithm** solves the **single-source shortest-path problem** for graphs with **non-negative edge lengths**.

Given a source vertex `s`, it finds the shortest distance from `s` to every other vertex.

### Conditions

* Directed graph
* Edge lengths are **non-negative**
* Negative edge lengths are **not allowed**

---

## Why Dijkstra?

**BFS** finds shortest paths when every edge has the same length.

Dijkstra works when edges have **different non-negative lengths**.

For example:

```text
A --2--> B
A --5--> C
B --1--> C
```

The shortest path from `A` to `C` is:

```text
A → B → C
2 + 1 = 3
```

---

# Algorithm

Dijkstra maintains a set `X` of vertices whose shortest-path distances are known.

Initially:

```text
X = {s}
dist(s) = 0
```

At each step:

1. Consider edges going from `X` to an unexplored vertex.
2. Calculate the **greedy score**:

```text
dist(v) + length(v, w)
```

3. Choose the unexplored vertex with the **smallest score**.
4. Add it to `X`.
5. Record its shortest distance and path.
6. Repeat until all reachable vertices are processed.

### Pseudocode

```text
X = {s}
dist(s) = 0

while there are unexplored vertices:

    choose edge v → w crossing from X to outside X
    with minimum dist(v) + length(v, w)

    add w to X

    dist(w) = dist(v) + length(v, w)
```

---

# Why Does It Work?

The correctness proof uses **induction**.

### Base Case

The shortest distance from the source to itself is:

```text
dist(s) = 0
```

### Inductive Step

Suppose all vertices already in `X` have their correct shortest-path distances.

When Dijkstra chooses the next vertex `w`, any path from `s` to `w` must eventually cross from `X` to an unexplored vertex.

Because all edge lengths are **non-negative**, extending a path cannot make it cheaper.

Therefore, the smallest greedy score gives the shortest possible path to `w`.

So `w` can safely be added to `X`.

By induction, all computed shortest-path distances are correct.

---

# Why Negative Edges Don't Work

Dijkstra requires:

> **All edge lengths ≥ 0**

With negative edges, a vertex that has already been processed can later be reached by a cheaper path.

This breaks Dijkstra's greedy choice.

Therefore:

**Dijkstra → non-negative edge lengths**

For graphs that contain negative edge lengths, algorithms such as **Bellman-Ford** are needed instead.

---

# Efficient Implementation Using a Heap

A simple implementation repeatedly scans all frontier edges to find the smallest greedy score.

This can take:

**O(MN)**

where:

* `N` = number of vertices
* `M` = number of edges

A **heap (priority queue)** makes this much faster.

The heap stores vertices with keys representing their current best-known distance.

### Heap Operations

* Extract minimum → `O(log N)`
* Decrease key → `O(log N)`

Each vertex is extracted once, and each edge can cause at most one key decrease.

Therefore, the running time is:

**O(M log N)**

This makes Dijkstra practical for large graphs.

---

# Key Takeaways

* **Dijkstra:** single-source shortest paths.
* Works only with **non-negative edge lengths**.
* Uses a **greedy** choice.
* Maintains a set `X` of processed vertices.
* Chooses the unexplored vertex with the **smallest greedy score**.
* **BFS** is for equal edge lengths; **Dijkstra** handles different non-negative lengths.
* A **heap/priority queue** gives an efficient implementation.
* Heap implementation: **O(M log N)**.
* Negative edges → use an algorithm such as **Bellman-Ford**.
